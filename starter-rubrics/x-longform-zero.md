# Starter Rubric：X 长内容（长帖 / Article / 长 thread）— v0 cold-start 占位

适用于主要在 X 上发长内容的账号：Premium 长帖（帖内长文本，"显示更多"折叠）、X Articles、10 条以上的长 thread。

**这是占位 rubric，会打错。**长内容发得慢、样本攒得慢——前 5 条中枢误差 ±60% 是常态。跑满 5 条完整闭环后提议第一次 `/cheatx-bump`。

> 本文件会被复制成你项目里的 `rubric_notes.md`，是 blind 打分 sub-agent 唯一能读的规则文件。只放通用语言；具体帖子、链接、复盘数字、回复原文写 `rubric-memo.md`。

---

## 和短帖 rubric 的区别

维度和 [x-post-zero.md](x-post-zero.md) 是同一套 8 维（同样对齐 X 推荐算法预测的用户行为），区别在三处：

1. **HK 判断的是"折叠之前"**：长帖在信息流里只露出开头一段，Article 只露出封面 + 标题 + 摘要。读者决定点不点"显示更多"/ 点不点进 Article，只看这一屏
2. **DW 和 SV 权重更重要**：长内容的价值主要在"点开后读完"和"收藏留着"，所以 v0 给这两维 ×1.5（短帖 v0 是等权）
3. **复盘窗口 T+7d**：长内容除了 For You 的 48 小时，还有搜索、收藏回看、被引用的长尾

---

## v0 综合分公式

```
composite = (HK + RP + SV×1.5 + RS + DW×1.5 + FT + NF) / 8 × 2.0  −  NR × 0.4
```

- 每维 0-5 整数；composite 0-10（低于 0 记 0）
- SV、DW ×1.5 是基于"长内容靠读完和收藏"的先验，**不是数据拟合**。第一次 bump 重点复审

---

## 8 个维度（长内容版锚点）

### HK — Hook（折叠前钩子）
- **0** — 开头是背景介绍 / 自我介绍 / "最近很多人问我……"
- **3** — 开头点明了主题和读完能得到什么
- **5** — 折叠前那一段本身就是一个完整的钩子：一个具体的结论 + 一个让人必须展开才能知道的"为什么 / 怎么做"。Article 的标题和封面独立就能让目标读者点开

### RP — Reply pull（回复牵引）
- **0** — 完整封闭的教程，读完没什么可说
- **3** — 有可讨论的判断
- **5** — 结尾留了一个读者能用自己经验回答的问题或分歧点（不是"欢迎留言"式话术）

### SV — Save & send（收藏 / 私信价值，×1.5）
- **0** — 读一次就够
- **3** — 有几条可用信息
- **5** — 读者会收藏留着下次照做（步骤 / 框架 / 模板 / 资源清单 / 数据），或者会私信给正在做这件事的朋友

### RS — Repost & quote（转发 / 引用身份价值）
- **0** — 转了对转发者没有意义
- **3** — 中性可转
- **5** — 转发等于"这就是我一直想说的"；或者内容里有一个能被单独截出来引用的判断

### DW — Dwell（停留密度，×1.5）
- **0** — 注水：同一个意思反复说，段落长、没有结构
- **3** — 结构清楚，能读完
- **5** — 每一节都在推进；小标题 / 列表 / 例子让人在手机上也能顺着读完；结尾兑现了开头的承诺

### FT — Follow trigger（关注转化）
- **0** — 看不出作者是谁
- **3** — 看得出作者懂这个领域
- **5** — 一手经验 / 独家数据 / 一个会持续输出的系列，读者读完会想"这个人后面还会写什么"

### NF — Niche fit（圈层契合）
- **0** — 和你平时的话题、你的关注者完全无关
- **3** — 相关领域
- **5** — 正中你的核心话题，用的是这个圈子的语言

### NR — Negative risk（负反馈风险，扣分项）
- **0** — 没有风险
- **3** — 标题党（标题 / 开头承诺的东西正文没兑现）、硬广植入
- **5** — 误导性信息、抄袭搬运、引战

## 发布条件（协变量，必记不打分）

同 x-post-zero：形态、媒体、外链、发帖时段、粉丝数、Premium、距上一条帖子、语言。长内容额外记：**字数**、**小标题数**、**Article 是否有封面图**。

---

## Bucket 预测：倍数桶

基线 = 同形态（`long` 或 `article`）最近 10 条已复盘的曝光中位数；不足 3 条用 `all`；都没有 → `max(100, 粉丝数 × 0.3)`。

| Bucket | 范围 |
|---|---|
| `退步` | < 0.3× 基线 |
| `持平` | 0.3 – 1× |
| `命中` | 1 – 3× |
| `小爆` | 3 – 10× |
| `大爆` | > 10× |

次要押注（必填）：
- **收藏 / 赞比**：`<0.2` / `0.2–0.5` / `>0.5`——长内容的 SV 主要从这里检验
- **互动率**：`<1%` / `1–3%` / `>3%`
- **新增关注**（数据可得时）：押一个区间

## 复盘窗口

默认 **T+7d**。T+48h 时可以先抓一次快照写进 report.md（标 `early_snapshot`），但校准用 T+7d 的数。

---

## 已知会打错的地方

1. **大号转发 / 引用是外生冲击**——复盘时标 `exogenous_boost`
2. **长度惩罚没有单独维度**：太长的长帖在 DW 里扣分，但"多长算太长"每个圈子不一样，复盘积累后再定
3. **Article 的曝光口径和帖子不同**：Article 本身的阅读数和推广它的那条帖子的曝光要分开记；预测时写清楚押的是哪个数

## 打分速度

每维 30 秒；相信第一个整数；先盲打再看锚点。
